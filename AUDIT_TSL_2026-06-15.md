## A. Architecture (vue d'ensemble) [V]

```
Navigateur client (winshirt.fr)
  └─ app block "Personnaliser" (extensions/textilelab-button)
       └─ tl-modal.js (servi via App Proxy /apps/textilelab/tl-modal.js)
            └─ iframe modal → textilelab-studio.html (Railway backend)
                 └─ apiFetch → /api/* (backend Express)            ← header X-Shop-Domain
                 └─ ajout panier → postMessage → tl-modal → /cart/add.json (domaine boutique)

Admin marchand (admin.shopify.com embed)
  └─ shopify-embed.html / textilelab-admin.html (App Bridge + session token)
       └─ /api/* (backend Express)                                 ← Authorization: Bearer <session token>

Backend Express (server.js)
  ├─ middleware: CORS, JSON, logger, checkSubscription (billing gate)
  ├─ routes/*  (22 fichiers, ~120 endpoints)
  ├─ db/ (SQLite, scopé shop_id) + utils/ (crypto, cloud, mockups, ftp, logger)
  └─ 2 déploiements Railway (public + Custom WinShirt) sur le MÊME code
```

**Points structurels notables :**
- **[V]** Le backend sert le studio ET les API ET le proxy. Mono-repo, mono-process.
- **[V]** Résolution du shop : `routes/_shop-context.js` (session token > ?shop > header X-Shop-Domain > bootstrap).
- **[?]** Deux configs Shopify (`shopify.app.toml` public, `shopify.app.winshirt.toml` Custom) — divergence de scopes à surveiller (`write_products` seulement sur Custom).

## C. Ce qui est sain (vérifié) [V]

- Isolation multi-tenant DB : tables scopées `shop_id`, helper `db/settings.js` (chiffrement AES-GCM des secrets).
- Résolution shop robuste (`_shop-context.js`) couvrant embed/admin/proxy/bootstrap.
- App Proxy : HMAC correct (concaténation sans séparateur), routes `/`, `/editor`, `/designs/:id`, `/tl-modal.js`.
- Webhooks GDPR + uninstall présents (`routes/shopify.js`).

## D. Méthode de vérification recommandée (pour ne plus sur-affirmer)

1. **Test à froid** : installer l'app sur un dev store neuf → vérifier page embed non blanche, OAuth, scopes.
2. **Parcours storefront complet** sur 2-3 thèmes (Dawn + 1 autre) : bouton → studio → 1 face / 2 faces → panier → **comparer badge studio == panier**.
3. **Checkout en sandbox** (sans payer) : vérifier les lignes et le total.
4. **GDPR** : déclencher les 3 webhooks, vérifier réponses 200 signées.
5. Cocher chaque point du **CDC validé** un par un avant toute affirmation « prêt ».

> Tant que D1→D5 ne sont pas tous verts, le statut reste « **en finition, pas prêt pour soumission** ».
